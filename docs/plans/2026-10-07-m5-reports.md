## Shared design

- **API:** `/api/v1/admin/reports/<name>` (`RequireRole(admin, manager)`), one handler per report
  returning JSON. The **same handler** answers `?format=csv|xlsx|ods` with `writeSheet` over
  **every** row in range (never the page). Range = `listRange(c)` (`reports.ResolveRange`
  presets + from/to, `to` inclusive of its whole day). Paged detail = `?offset=` +
  `Page[T]` + "Show older". Headline totals always come from SQL over the whole range or from
  the full row set — never from a page.
- **One report kit** (`web/src/features/reports/kit/`), so no report hand-rolls its frame:
  - `ReportPage` — `PageHead` + `RangePicker` + Export menu (csv / xlsx / ods carrying the live
    filters) + Print (browser print of the page; the shell hides chrome under `@media print`).
  - `reportSearch` — TanStack Router `validateSearch` (preset / from / to + report-specific keys),
    so **filters live in the URL** (spec §6.1) and survive reload / share.
  - `KpiTiles` (value, optional ▲▼ delta vs the previous equal period, hidden when the baseline
    is 0), `BarCell` (in-row bar = share of the top row), `AgingBar` (0–30 / 31–60 / 61–90 /
    90+), `ShareCol`.
  - Charts: the M4 `components/charts/Chart.tsx` (lazy ECharts, palette-themed, `--chart-1..4`),
    each with a **Table** view that is the default on phones. No new chart library.
  - Detail lists: `DataList` (table ≥ md, cards at 360px).
- **Reports hub** `/admin/reports`: karots-pos's three groups (Sales & Customers · Money & Profit ·
  Inventory & Suppliers) + a **More** group from a new `slots.reportCards` (TS) + the **Live views**
  strip (Cash flow, Activity, Receipts). Tax only when `settings.tax_registered`.
- **Redirects kept from karots-pos** (as router redirects): `/reports/sales-trend` → Sales,
  `/reports/tender` → Finance, `/reports/warranty` + `/damage` → Losses, `/reports/finance` →
  `/admin/finance` (M4's hub *is* the Finance report; it gains the P&L export here),
  `/reports/low-stock` → `/admin/reorder` (M3's reorder *is* the low-stock tool; it gains the
  print here), `/audit` → Activity with `source=audit`.
- **Shop timezone everywhere:** a day / week / month bucket and an hour bucket are taken in
  `datetime.Location` (`created_at AT TIME ZONE $tz`), never the DB session's zone.
- **Legacy cleanup:** delete `reports.APIHandler` / `reports_api.go`'s handler part once the admin
  reports land (keep `ParseRange` only if still used — else delete it too).

## Upgrades over karots-pos (flaws found while planning, not copied)

1. **Trend revenue disagreed with the P&L.** `SalesByPeriod` sums line subtotals: it ignores the
   bill discount and includes pass-through face value, while `Compute` uses sale totals net of
   pass-through. Finance's M4 trend already shows it (the line sums to more than the Revenue tile
   whenever there's a bill discount). Fix: per-line revenue × `sales.PaidFactorSQL`, pass-through
   excluded, returns netted — so Σ trend = `PL.Revenue` and Σ profit = `PL.GrossProfit` over the
   same range. Domain bug → also a bug-fix-only commit in karots-pos.
   **Done (suite `5f108d3`, karots-pos `275d885`):** found while writing the test — the P&L itself
   took returns back at the sticker price while its gross is the discounted total, so a fully
   returned discounted sale went *negative*. `Compute.Returns` now uses `PaidFactorSQL`, and
   `SalesByPeriod` reuses the sales list's per-sale aggregate (`sales.ProfitAggSQL`, exported).
2. **Day buckets were UTC.** `date_trunc` on `created_at` used the session zone; a 00:30 Colombo
   sale fell on the previous day in Sales trend, the dashboard trend and Tax. Buckets now in shop
   time (memory `reports-revamp`: "existing day-grouped reports still use UTC day boundaries").
   Also in karots-pos, same commit as 1.
3. **Activity merged every row in memory** (20k per source, paged in Go) and **audit capped at
   500.** Now keyset-paged: `activity.Filter` gains `Before *Cursor` + `Limit`; the core `UNION ALL`
   orders by `(when DESC, source, id DESC)` and each contributor gets the same cursor, the merge
   keeps the first `Limit`, and the last row is the next cursor. One tx writes several rows with
   the same `now()`, so the cursor is the tuple, not the time alone. `/audit` is Activity with
   `source=audit` — no second, capped log.
4. **Returns report was filtered by the sale's date.** A refund given today on last month's sale
   never showed in "today". The report now lists by **return date** (`sale_returns.created_at`)
   with the sale date as a column, refund valued at what was paid. A one-line note says the P&L
   nets returns into the sale's own period (unchanged, so the P&L doesn't move under anyone).
5. **Unbounded / client-side lists:** batches, cash register, recipe variance, returns and dues
   were whole-table reads sliced in Go. Totals stay whole-set; the screen pages 50 with Show older;
   exports carry everything.

## Review Focus

1. **Totals vs pages vs exports.** A range with > 50 rows: the KPI totals equal the sum over every
   row; the export has exactly `count` rows; Show older reaches the end without a gap or duplicate.
   Tests: tasks 1, 3, 7 (Go, rows inserted in a rolled-back tx).
2. **Shop-time day edges.** A sale at 00:30 Colombo (= 19:00 UTC the day before) is "today" on the
   dashboard and in today's trend bucket and peak-hours cell; a custom `to` includes its whole local
   day. Test: task 0.
3. **Trend ↔ P&L agreement** with a bill discount, a pass-through line and a partial return in
   range: Σ trend revenue = `PL.Revenue`, Σ trend profit = `PL.GrossProfit`. Test: task 0.
4. **Empty and zero baselines.** An empty range renders zeros and an empty-state chart, never
   NaN / Infinity %; a delta is hidden when the previous period is 0; Pareto / share / margin with
   zero revenue show "—". Tests: Vitest on the kit's `delta()` / `share()` (task 0), Go empty-range
   test per group handler.
5. **Who may see what.** Activity / audit: admin only (manager → 403, cashier → 403); the system
   user never appears in rows or the Who filter; cost / profit columns follow `canSeeCost` for
   managers as the M4 Sales list does. Tests: task 7, plus a manager case in task 1.
