# M7.1 Customer requests — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.
> Same shape as M7.0. Opus executes and reviews, one commit per step, and UI gates are self-reviewed (4 combos, 1366 + 360).

**Goal:** Customer requests, reinterpreted. Repeat asks count instead of duplicating, a request closes three ways (make / link / won't stock), a waiting list says whom to call once the item is in stock, and a no-match till search offers to note a request.

**Spec:** `docs/specs/2026-10-11-m7-1-requests-design.md`. Fork source: karots-pos `plugins/requests/` (read-only).

## Global constraints

- **Core never references a plugin and never changes for one plugin.** The only core change is the generic seam E (Task 1). `make check-core` must pass after every task.
- `cmd/server/enabled_plugins.go` and `web/src/plugins/enabled-plugins.ts` are committed **core-only**. Use `make plugins P=requests` (or `P=all`) to work and `make core-only` before committing.
- The plugin's JSON types live in `plugins/requests/api.go`, mirrored by hand in `web/src/plugins/requests/types.ts`. Errors go through `apperr`, JSON is camelCase, money is decimal strings, and files are ≤ 500 lines.
- Plugin pages use the admin kit and theme tokens only, and must work at 360px in Studio / Night × light / dark.
- No Claude / AI attribution in commits.

## Review focus

1. **A karots-pos backup with `requests` rows.** They must restore unchanged, each read as one ask, and a converted row whose product has stock and whose phone is set lands in To call (Task 6).
2. **Merge.** The merged request's own first ask must become an ask row on the target, nothing may be lost, and merging into itself or into a non-open request must be refused (Task 2).
3. **Clear done** must never delete a won't-stock row or anything with someone still to call (Task 2).
4. **A cashier on admin routes** gets 403 (Task 3).
5. **A core-only build.** Quick item looks exactly as before (Task 1).

### Task 2: Requests Go — plugin, migrations, store

**Files:** `plugins/requests/{plugin.json,requests.go,store.go,store_db_test.go}`, `plugins/requests/migrations/{embed.go,0001_requests.sql,0002_asks.sql}`.

- [ ] **Step 1:** copy `0001_requests.sql` and `embed.go` from karots-pos **byte for byte** (only the module path changes in embed.go, if it has one).
  - Write `0002_asks.sql` per spec §4: the two columns, `request_asks` plus `idx_request_asks_request (request_id)`, and a Down migration.
  - `plugin.json`: key `requests`, name "Customer requests", import `karots-suite/plugins/requests`, version `2.0.0`, and a description that mentions asks, the three ways to close and the waiting list.
- [ ] **Step 2: failing DB test** (`store_db_test.go`). Skip without DATABASE_URL. It runs both migrations with `db.RunMigrationsTable(..., "goose_db_version_requests")`, makes its own products via SQL ("Req Test <nanos>", one with a `stock` row of quantity 5, one with none), and cleans up in `t.Cleanup`. Cases:
  - `Add` → `List(tab "open")` has it with `Asks` length 1 (id 0).
  - `AddAsk` → 2 asks, sorted first by asks.
  - `Similar("red umb")` finds "Red umbrella large", while `Similar("blue")` doesn't. A declined request is found and carries its reason; a converted request whose product has stock is not.
  - Link to the stock-0 product with a phone set → stage `waiting` (Open tab). Then set its stock to 5 → stage `call`. `MarkCalled(id, 0)` → stage `done`.
  - Link with no phone anywhere → `done` straight away.
  - `Decline` with reason → `done`. `ClearDone` deletes the converted done row and keeps the declined row and a `call` row.
  - `Merge(b, into a)`: `a` gains b's first ask (name / phone / created_at kept) and b's extra asks, and b is gone. `Merge(a, a)` → error, and merging into a declined request → error.
  - `Reopen` clears `product_id` and `reason`.
- [ ] **Step 3:** `make plugins P=requests && go test ./plugins/requests` → FAIL.
- [ ] **Step 4: implement `store.go`.**
  - Types:
    - `Request{ID, Note, Status, Reason, ProductID *int64, ProductName, Stage, Asks []Ask, LastAsked time.Time}`
    - `Ask{ID int64 (0 = the row), Name, Phone, By (user name), At, CalledAt *time.Time}`
  - Write calls: `Add`, `AddAsk` (refuses stage call / done → `ErrClosed`), `UpdateNote`, `UpdateAsk`, `DeleteAsk` (id > 0), `MarkCalled`, `Delete`, `MarkConverted(id, productID)` (used by both make and link), `Decline`, `Reopen`, `Merge`, `ClearDone`.
  - Read calls:
    - `List(ctx, tab, q, limit, offset) ([]Request, Counts, error)`
    - `Similar(ctx, q) ([]Request, error)`
  - The stage is **one SQL CASE** (`stageSQL`) used by List, Similar and ClearDone. "Someone to call" is an `EXISTS` over the asks union.
  - The asks union (`asksSQL`) is `SELECT 0, r.id, customer_name, … FROM requests r UNION ALL SELECT id, request_id, … FROM request_asks`, loaded for a page of ids in one query and joined to `users` for the name.
  - `Merge` and `ClearDone` each run in one tx.
- [ ] **Step 5: `requests.go`.** `init` → `plugin.Register`, `Name()` "Customer requests", `Key()` "requests", `Migrations()`. `Setup` adds the data group (`requests`, `request_asks`). Routes come in Task 3.
