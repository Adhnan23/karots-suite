# Palettes part 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every look value in the SPA is a token. There are four built-in palettes for theme **Dock**, and the system user can make custom palettes (stored as CSS in the DB) with an editor on Appearance, plus Export / Import.

**Architecture:**
- Palettes are CSS blocks keyed `:root[data-ui="dock"][data-palette="<id>"]`, for light and dark.
- Built-ins are bundled from `web/src/theme/palettes/dock/*.css`.
- A custom palette is a full palette file in the `palettes` table, served as `text/css` from a public endpoint that `index.html` links.
- The editor parses and builds that CSS with a pure module (`paletteCss.ts`), and previews through a draft `<style>`.

**Tech Stack:** Go / Echo / sqlx / goose; React, TS, Tailwind v4 `@theme inline`, motion/react, Vitest, Playwright.

**Spec:** `docs/specs/2026-10-21-palettes-design.md`

## Global Constraints

- Core stays plugin-inert. Components use tokens only and never branch on the palette.
- Files stay ≤ 500 lines. Every admin screen works at 360px.
- Studio and Night look **exactly** as they do today after Tasks 1–2 (same values, only moved onto tokens).
- Custom palette CSS is ≤ 64 KB, the name is required and unique, and every write is system-user only. The active palette can't be deleted.
- **Built-ins are never exported.** Import refuses a file whose header names another theme.
- File header: `/* karots-palette theme=dock name=<name> base=<base id> */`.
- Durations stay ≤ 350 ms. `prefers-reduced-motion` turns motion off. `prefers-reduced-transparency` keeps working.
- Migration `00011_palettes.sql`. Run `make types` after `dto.go` changes. Never hand-edit `types.gen.ts`.
- No AI attribution in commits.

## Review Focus

1. **A custom palette on the login page.** Signed out, after a reload, it must show at once, with no flash of Studio. The pre-paint script and the `<link>` load before first paint (Task 6 e2e).
2. **Saving while the same palette is active.** The new CSS shows without a hard reload: the `<link>` href is cache-busted (Task 6).
3. **Leaving the editor unsaved.** The saved look comes back, and the draft `<style>` and mode flip are removed (Task 8 test).
4. **An imported hand-written file with rules beyond tokens.** The extra rules survive into Custom CSS and back out on export unchanged (Task 5 test).
5. **A legacy shop with a brand colour or radius set.** It looks the same after the update. Choosing a palette clears the legacy values (Task 7 Go test + Task 1 appearance test).

### Task 5: `paletteCss.ts`, read and write palette files

**Files:**
- Create `web/src/features/appearance/paletteCss.ts`, `paletteCss.test.ts`

**Interfaces:**
- Produces:
  - `type PaletteDoc = { theme: string; name: string; base: string; light: Record<string,string>; dark: Record<string,string>; extra: string }`
  - `parsePalette(css: string): PaletteDoc`
    - Reads the header comment, the `:root[...][data-palette="x"]` block (light) and the `[data-theme="dark"]` block (dark).
    - Ignores the `prefers-color-scheme` copy.
    - Collects `--*` declarations. Everything else (other rules, non-token declarations, `@media` blocks other than the dark copy) goes to `extra`, verbatim.
  - `buildPalette(doc: PaletteDoc, id: string): string` emits:
    - the header
    - the light block, with `color-scheme: light`
    - the dark block, with `color-scheme: dark`
    - `@media (prefers-color-scheme: dark) { :root[data-ui="dock"][data-palette="<id>"]:not([data-theme="light"]) { …dark… } }`
    - then `extra`

    Token order follows `TOKENS`, and unknown tokens are kept after them.
  - `paletteId(customId: number) => 'custom-' + customId`

  Built-in sources come from `import.meta.glob('@/theme/palettes/dock/*.css', { query: '?raw', import: 'default', eager: true })`, exported as `builtinDoc(id): PaletteDoc`. Built-ins have no header, so the theme is `dock`, the name comes from `PALETTES` and the base is the id.

**Interfaces:**
- `draft.ts`:
  - `startDraft(id: string): void` sets `html[data-palette]` to the id and inserts `<style id="ks-palette-draft">`
  - `updateDraft(css: string): void`
  - `previewMode(m: 'light'|'dark'): void` sets `data-theme` and remembers the device's `ks-mode` value
  - `endDraft(saved: Appearance): void` removes the style, restores `data-theme` from `ks-mode`, and calls `applyAppearance(saved)`
- `presets.ts`:
  - `applyMaterial(tokens: Record<string,string>, m: 'solid'|'frosted'|'liquid', mode: 'light'|'dark'): Record<string,string>`, which sets `--card` alpha, `--bar`, `--glass`, `--card-glass` and the `--shadow` rim
  - `applyMotion(tokens, feel: 'calm'|'lively', speed: number /* 0.5–1.5 */)`, which writes `--dur-*` (base 120/220/350 ms × speed, capped at 350 ms), `--ease` (calm `.2,.8,.2,1` / lively `.2,1.25,.4,1`) and `--lift` (0 / 2px)
  - `materialOf(tokens): 'solid'|'frosted'|'liquid'`, derived from `--glass` / `--card-glass`, for showing the current pick

**Editor:**
- **Header.** The name (editable), Light | Dark segmented control, Reset to base, Save.
- **Groups**, each a collapsible section:
  - **Colours.** Every `TOKENS` entry with `kind:'color'`, grouped: background, surfaces, text, brand, selected, money, hero, charts. Each has a native colour input (hex only; for rgba values show the text box only) and a text box.
  - **Material.** Three choices plus a blur slider (0–32 px) that rewrites the blur in `--glass` / `--card-glass`.
  - **Background.** Art on/off (`--bg-art` none ↔ the base palette's art) plus the background colour.
  - **Depth.** Shadow strength (none / soft / strong presets on `--shadow` / `--shadow-float`), glow on/off.
  - **Shape.** Radius slider 0–28 px (it writes `--radius` and `--radius-sm` = round(r × 0.7)), Pill: Round / Soft (`--pill` 9999px / `var(--radius-sm)`), Border 0 / 1 / 2 px.
  - **Motion.** Calm | Lively, Speed slider.
