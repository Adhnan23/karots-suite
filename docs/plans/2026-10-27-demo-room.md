# M8d Demo Room Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One double-click demo binary that runs the *real* suite as five believable, year-old, busy shops (plus
make-your-own), with printer emulators, a watermark, a cheat menu and a rotating-code lock — without changing how
the suite behaves in a real shop.

**Architecture:** `cmd/demo` is a **launcher** (embedded PostgreSQL in a temp dir, lock, shop picker, reverse proxy
that injects the demo chrome, two TCP printer listeners) that re-executes **itself** as a **child** per shop
(`karots-demo -child …`): the child calls `plugin.Only(keys)`, migrates a fresh database, generates the shop's
history through the real services / API, then serves `app.BuildServer` exactly as `cmd/server` does. Switching shop =
kill child, drop its database, start another. All demo code lives in `cmd/demo` and `internal/demo/…`; shop builds
never import it.

**Tech Stack:** Go (Echo, sqlx, embedded-postgres via `internal/filedb`, `net/http/httputil`), a separate small Vite
entry for the chrome (`web/demo/`, React + the suite's theme tokens), Playwright MCP for gate shots.

**Spec:** `docs/specs/2026-10-27-demo-room-design.md` (read it first — this plan argues from it).

## Global Constraints

- **The demo must not affect the suite** (user): every seam added to core is inert unless `cmd/demo` calls it; no
  env var / flag / setting a shop could trip; no extra work on a shop's request path. `cmd/server` behaviour is
  byte-for-byte unchanged apart from pure code moves.
- Core never imports `internal/demo…` or names a plugin; `make check-core` passes (it learns that `cmd/demo/` and
  `internal/demo/` are not core, like `cmd/bootstrap/`).
- Plugins get **no demo code**. Plugin data is made through each plugin's own `/api/v1/x/<key>/…` endpoints.
- No `if demo` branches anywhere in features, core API, core SPA or plugins.
- Money only via `cashflow.Move/MoveTx` (i.e. through the services that already do it); sales are the revenue truth.
- Files ≤ 500 lines, by concern. Theme tokens only in the chrome (`theme/guard.test.ts` style rules apply to
  `web/demo/` too — extend the guard's glob).
- Launcher listens on **127.0.0.1 only**. Everything (Postgres data, temp files) lives under one
  `os.MkdirTemp("", "karots-demo-*")` folder, removed on exit and on the next start (stale `karots-demo-*` folders
  older than the current process are deleted).
- Every shop: receipts **and** labels print as **Image**; printers point at the emulators (`tcp://127.0.0.1:<port>`).
- Watermark text: `DEMO — Karots Business Suite · <OwnerName> · <OwnerPhone>`; **ask the user for the exact name and
  number in Task 9** (placeholder `Karots` / `07X XXX XXXX` until then).
- Shop ready ≤ ~30 s after picking on the owner's laptop (measure in Task 6; template fallback only with a
  date-column coverage test, spec §"The shop's history").
- Built-in shops (spec, user-approved):

  | key | Name | Plugins | Palette (`settings.skin`) | Receipt style |
  |---|---|---|---|---|
  | `grocery` | Grocery / mini-mart | — | `studio` | `classic` |
  | `pharmacy` | Pharmacy | pharmacy, alternatives, productplus, requests | `lagoon` | `minimal` |
  | `phone` | Phone & repair | repairs, recharge, combos, documents | `synthwave` | `ticket` |
  | `hardware` | Hardware / building | clearance, productplus, documents, requests | `bazaar` | `grid` |
  | `everything` | Everything shop | all compiled plugins | `aurora` | `cards` |

## Review Focus

1. **Picking a shop twice in a row / switching mid-generation** — the old child must be dead, its DB dropped, no port
   or Postgres leak; the second pick starts clean. (Test in Task 5.)
2. **Opening the demo again after a crash** (child or launcher killed) — leftover temp folder and Postgres are
   cleaned, demo starts. (Test in Task 5, uses `filedb`'s leftover stop.)
3. **A day that has just begun (00:05) or a Sunday** — "today" still shows sales and an open till; generation never
   writes a timestamp in the future. (Test in Task 6.)
4. **Data integrity of a generated shop** — `datacheck.Run` finds nothing, cash drawer totals match sales, every
   credit balance equals its ledger. (Test in Task 6 and Task 7, per shop.)
5. **Wrong / expired lock code and direct URL access** — every launcher and proxied route (including `/api/v1/*` and
   print pages) refuses without the lock cookie; the hourly code from the previous window is accepted (skew 1), older
   is not. (Test in Task 4.)
