# Cheques Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cheque becomes a payment method everywhere money moves (till, customer payments, supplier payments, expenses), held as Pending until an admin / manager marks it Cleared, Bounced or Cancelled, with a Money → Cheques page, a cheque colour and dashboard reminders.

**Architecture:** One `cheques` table (direction `in` / `out`, links to the sale payment / customer payment / supplier payment / expense) owned by a new core package `internal/features/cheques`. Received cheques move External → a single **Cheques in hand** locker (kind `cheque`) when taken; given cheques move nothing until Cleared. A new core package `internal/features/payout` is the one way to *give* money (supplier payment or expense, from a place now or by cheques). Sales reach cheques through a DI seam (`sales.WithChequeLeg`), the same shape as `WithNonCashLeg`, because `cashflow` imports `sales`.

**Tech Stack:** Go (Echo, sqlx, goose, Postgres 17), React + TS (TanStack Query / Router, Tailwind v4 tokens), Vitest, Playwright.

**Spec:** `docs/specs/2026-10-29-cheques-design.md`

## Global Constraints

- **Core is plugin-inert:** no core Go file, core `web/src` file, comment, test or doc string in core code names a plugin (`make check-core`). Core seams are generic ("a supplier payment", "an expense"); only Task 12 touches `plugins/` and `web/src/plugins/`.
- Money only through `cashflow.MoveTx` inside the caller's transaction. Sales stay the source of truth for revenue.
- Go DB tests run as `set -a && . ./.env && set +a && go test ./<pkg> -run <Name>` (written `ENV go test …` below). Never while Playwright runs.
- Migrations: `00014_cheque_method.sql` (`-- +goose NO TRANSACTION`, `ALTER TYPE payment_method ADD VALUE IF NOT EXISTS 'cheque'`) and `00015_cheques.sql` (everything else). Never touch the `wallet` / `deposit` values other code adds.
- DTOs only in `internal/api/dto*.go` → `make types`; never edit `types.gen.ts`. JSON camelCase, money as decimal strings, dates `YYYY-MM-DD`.
- Files ≤ 500 lines. Theme tokens only (`theme/guard.test.ts`); every admin screen works at 360 px.
- Only admin + manager change a cheque (the `/api/v1/admin` group). Cashiers take / write cheques wherever they already take / pay money.
- Outside the till a payment is **one method**; method `cheque` carries **one or more** cheque lines whose amounts are the payment's amount. Mixing cheques with cash happens only at the till (a call made here — see the hand-off).
- Commits: one per task, on `main`, conventional style, **no Claude / AI attribution lines**.
- Words on screen: "Cheque", "Pending", "Cleared", "Bounced", "Cancelled", "Cheques in hand", "After cheques", "Cheques to deposit", "Your cheques due", "Not paid — cheque bounced" (or "… cancelled").

## Review Focus

1. **A double tap on Cleared / Bounced** — the second request must get a Conflict ("this cheque is already cleared"), never move money twice. (Task 2: `SELECT … FOR UPDATE` + status check; test `TestStatusChangeIsFinal`.)
2. **A backup from before cheques restored** — restore TRUNCATEs `lockers`, so Cheques in hand is gone; the first cheque after it must still work. (Task 1: get-or-create `lockers.ChequesInHandTx`; test `TestChequesInHandRecreated`.)
3. **A bounced supplier cheque whose bills were since paid some other way** — reopening must never take a bill's `paid_amount` below 0 or reopen more than this payment allocated. (Task 2: `reopened` column + cap; test `TestSupplierBounceCapsReopen`.)
4. **An expense voided or edited while its cheque is Pending** — refused ("cancel the cheque first"), else the cheque would later clear money for an expense that no longer exists. (Task 5: test `TestExpenseVoidRefusedWhilePending`.)
5. **Clearing date before the cheque date or in the future, or a cheque cleared into a non-bank place** — refused. (Task 2: test `TestClearDateAndPlace`.)

Money rules (spec "The money"):
- `ReceiveTx`: requires `k.CustomerID > 0`, `l.Number`, `l.Amount > 0`; inserts `direction='in'`; `MoveTx{From: External(), To: Locker(chequesInHand), Amount, Reason: "cheque " + number, ReceiptKind: kindFor(k) /* "payment" for a sale, "customer_payment" for a customer payment */, Ref: sale or customer_payment ref, Party, ActorID}`.
- `GiveTx`: `l.LockerID` must be an active `bank` locker; inserts `direction='out'`; **no move**.
- `Clear` (`FOR UPDATE`, status must be `pending`, `cheque_date ≤ on ≤ today`): in → `intoLockerID` must be an active bank locker, `MoveTx{From: Locker(chequesInHand), To: Locker(into), ReceiptKind: "transfer", Ref: {Kind:"cheque", ID}}`, store `locker_id = into`; out → `MoveTx{From: Locker(drawnOn), To: External(), Recorded: true, ReceiptKind: "supplier_payment" | "expense", Ref: the supplier_payment / expense ref, Party}` so cash-flow reports read it like any bank payment. Sets `status`, `status_date = on`, `status_by`.
- `Return` (same lock + pending check): in → `MoveTx{From: Locker(chequesInHand), To: External(), ReceiptKind: "cheque_returned", Ref cheque}` and `customers.AddBalance(+amount)` (ignores the credit limit — never stop a sale). out + supplier → `suppliers.AddBalance(+amount)` and reopen that payment's allocations newest first: for each, `take = min(left, alloc.amount - alloc.reopened)`, `UnapplyPayment(purchase, take)` (paid_amount = GREATEST(paid_amount − take, 0); status `received` when it reaches 0, else `partial`), `reopened += take`. out + expense → `expenses.unpaid += amount`. No money moves for out.
- `Fix`: pending only; amount and person never change; given `LockerID` must be an active bank.
- Every change writes `audit_log` (entity `cheque`, entity id, detail e.g. "cleared into BOC current" / "bounced") through `audit.NewRepository(tx).Insert`, so history commits with it. `audit.ListFilter` gains `EntityID string` (`AND ($n::text IS NULL OR entity_id = $n)`).
- Built-in banks (`banks.go`): Bank of Ceylon, People's Bank, Commercial Bank, Hatton National Bank, Sampath Bank, Seylan Bank, Nations Trust Bank, DFCC Bank, NDB Bank, Pan Asia Bank, Union Bank, Amana Bank, Cargills Bank, HSBC, Standard Chartered, Regional Development Bank, National Savings Bank, Sanasa Development Bank.
